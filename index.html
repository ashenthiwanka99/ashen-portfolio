In numbers

5.0 s → 21 ms

One search across 20,000 documents, timed in testing before and after.

The problem

Searching for text anywhere inside a field cannot use an ordinary index, so PostgreSQL was reading every one of 20,000 documents on every search. It took about five seconds.

What I did

Added a trigram GIN index with pg_trgm, which indexes every three-letter slice of the text, then ran the same searches again and compared the query plans and timings.

The result

The same search came back in 21 ms, about 240 times faster. The same round of tuning made a count query 21 times faster and a token lookup 213 times faster.
